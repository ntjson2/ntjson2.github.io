Mineral Prospectivity Model

Mineral Prospectivity Model

  • Category: Machine Learning / Data Science
  • Stack: Python, scikit-learn
  • Task: Multi-label classification (5 metals)
  • Evaluation: Leave-one-state-out spatial cross-validation

The portfolio blurb

I designed, built, and honestly evaluated a mineral prospectivity model — a machine-learning system that predicts, for any point on a map, which of five metals (gold, silver, copper, lead, zinc) are most likely to occur there, based on rock type, deposit type, and location. Trained on 182 schema-locked, EAS-attested mining districts plus the USGS MRDS dataset, it uses strict leave-one-state-out spatial cross-validation and calibrated probabilities. Rather than oversell it, I published exactly where it does and does not generalize — the gold model predicts with F1 0.87 in-region, and I documented the honest out-of-region limits.

What it does (plain English)

Imagine you point to any spot on a map — say, somewhere in Nevada — and describe the rocks there (granite? volcanic? limestone?) and whether it has been mined before. The model looks back at the mining districts it already knows and answers: "New spots that look like this one, in this part of the country, with this kind of rock, usually turn out to have gold, sometimes silver and copper, rarely zinc." It returns a score from 0 to 1 for each of five metals. It is pattern-matching, not magic.

The problem it solves

Junior miners and exploration consultancies face a screening question every day: "Where should we look next, and for what?" That answer is usually someone's gut feel. A transparent, data-driven prioritization tool — one that also cites its supporting, on-chain-attested reference districts — turns that gut feel into a repeatable, auditable first pass. It is a prioritization / indicator, never a resource estimate.

What I built

ComponentDetail
Ground-truth data182 curated, schema-locked, EAS-attested mining districts (US, CA/BC, MX)
Volume dataUSGS MRDS (Mineral Resource Data System) — 267,964 deposit records used for augmentation
TaskMulti-label classification: predict presence of each of 5 metals per location
ModelOne-vs-rest logistic regression, one model per metal
Featuresstate, deposit type, development status, host rock type, lat/lon (rounded ±0.1 deg)
EvaluationLeave-one-state-out spatial cross-validation (honest standard for geology — no leakage)
CalibrationSigmoid probability calibration, validated on a strict out-of-region hold-out (CO + CA)
StackPython / scikit-learn only (no new dependencies)

Why the methodology matters: in geology, a model that cheats by testing on neighbors of its training points looks great but is useless. Leave-one-state-out CV forces the model to predict a state it has never seen, which is the real-world use case (new territory). Reporting that honestly is the differentiator.

Documented limits: with generic (unknown) geology, even a famous gold district scores low — real geology features are required for a meaningful output. Calibrated probabilities were validated on a strict out-of-region hold-out (Brier 0.29 / ECE 0.28).

Indicator / prioritization tool — not a resource estimate.

Method and limitations documented. Not NI 43-101 / JORC-compliant; not a deposit-finder.
